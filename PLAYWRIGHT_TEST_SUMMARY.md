## Test Cases

### TEST 1: LIVE MODE DETECTION
**Purpose:** Verify application is in LIVE mode
**What it checks:**
- Presence of "AI: Gemini" or "LIVE" indicator
- Absence of "Demo Mode" indicator
**Output:** Screenshot showing mode detection

### TEST 2: STATIC CHAT DATA DETECTION
**Purpose:** Detect static/demo chat responses
**What it checks:**
- Sends two unique math questions:
  - "TEST-LIVE-84721: What is 17 multiplied by 23?" (expected: 391)
  - "TEST-LIVE-93264: What is 19 multiplied by 17?" (expected: 323)
- Captures network requests to `/api/ai/chat`
- Verifies responses are different
- Verifies responses contain expected answers
**Output:** 
- Network request details (URL, method, status, payloads)
- Screenshots of responses
- Verification that responses are dynamic

### TEST 3: CAPABILITY SCORES DYNAMIC CHECK
**Purpose:** Verify capability scores are dynamic
**What it checks:**
- Capability scores are present in UI
- Scores change when scenario changes
- No static score generation
**Output:** Screenshots showing score changes

### TEST 4: GENERATE BRIEF
**Purpose:** Test brief generation workflow
**What it checks:**
- Network request to `/api/ai/chat` or `/api/ai/prepare`
- Brief content is generated
- Response is not empty
**Output:** 
- Network request details
- Screenshot of generated brief

### TEST 5: PRACTICE WITH UNIQUE INPUT
**Purpose:** Test practice evaluation with unique input
**What it checks:**
- Network request contains unique test input
- Evaluation is generated
- Response references unique input
**Output:**
- Network request details
- Screenshot of evaluation

### TEST 6: TRANSCRIPT ANALYSIS
**Purpose:** Test transcript analysis with unique content
**What it checks:**
- Network request contains unique transcript marker
- Analysis is generated
- Response references unique content
**Output:**
- Network request details
- Screenshot of analysis

### TEST 7: FULL WORKFLOW
**Purpose:** Test complete workflow end-to-end
**What it checks:**
- Scenario selection
- Brief generation
- Practice submission
- Evaluation generation
- Transcript analysis
- Complete workflow completion
**Output:** Screenshots at each step

## Network Request Analysis

The tests capture all network requests to AI endpoints and log:

### Request Details
```
Request: POST https://your-app.up.railway.app/api/ai/chat
Status: 200
Request payload: {
  "messages": [
    {
      "role": "user",
      "content": "TEST-LIVE-84721: What is 17 multiplied by 23?"
    }
  ]
}
Response payload: {
  "content": "391",
  "usage": { ... }
}
```

### What to Look For

1. **Request URL**
   - Should be `/api/ai/chat` or similar
   - Should match your backend endpoint

2. **Request Method**
   - Should be POST

3. **Request Status**
   - Should be 200

4. **Request Payload**
   - Should contain your test input
   - Should be properly formatted

5. **Response Payload**
   - Should contain AI response
   - Should not be empty
   - Should contain expected content

## Common Issues

### Issue: Tests timeout
**Cause:** AI responses taking too long
**Solution:** Increase timeout in `playwright.config.ts`:
```typescript
timeout: 180000, // 3 minutes
```

### Issue: Network requests not captured
**Cause:** Wrong URL pattern
**Solution:** Update URL pattern in test:
```typescript
const networkRequests = await captureNetworkRequests(page, /\/api\/ai\/chat/);
```

### Issue: Elements not found
**Cause:** Selectors don't match UI
**Solution:** Update selectors in tests to match your UI

### Issue: Responses don't contain expected content
**Cause:** AI not working or returning different format
**Solution:** Check network response payload

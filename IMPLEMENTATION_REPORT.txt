ARCHITECTURE CHANGES
Interaction owns artifact IDs and validated lifecycle transitions. Mode-specific local stores and local employee profiles partition state. Structured roleplay carries state and session/interaction identity. Semantic operation contracts are shared between frontend and backend. Response schema selection uses the operation name rather than searching user/context text. Evidence extraction precedes assessment, then a grounding judge and one intervention. Memory updates require their own judge and deduplicate independent sources. Historical evidence is appended rather than overwritten. Backend provider configuration, adapters, retries and real-provider fallback are preserved.

UX CHANGES
Added 28 performance moments, four complexity profiles, independent stakeholder seniority and reviewed natural-language intake. The plan hierarchy is objective, one risk, strategy, three main questions, up to three watch-outs and practice. Provenance and company guidance expand below; unknown commercial authority stays explicit. Context bars show customer, interaction, stakeholder, date, stage and capability. Practice results use qualitative readiness and expandable evidence/dimensions. Plan vs Actual includes intended/actual sources and preparation effectiveness. The next moment receives prior learning. Explicit Demo Mode has a banner, separate storage and one synthetic renewal seed. Added recovery boundaries and optional local company-context entry.

AI OPERATION CHANGES
13 documented semantic operations plus structured stakeholder response and provider diagnostic. Preparation uses two specialized calls. Practice has one call per turn and at most one invalid-output repair. Assessment uses extraction, rubric evaluation, grounding judge and conditional intervention. Transcript analysis separates facts, behavior, comparison, assessment/judge and coaching. No failed live request falls back to demo. No incomplete or failed practice produces an assessment. No arbitrary readiness percentage is computed.

KNOWN LIMITATIONS
- The local tests use an explicit fixture gateway. They verify application contracts, orchestration and failure handling, not the real model's semantic accuracy.
- Real-provider inference, rubric calibration, dynamism, prompt robustness and intervention usefulness still need deployed runtime validation.
- Local profiles are browser-state partitions, not secure authentication, server persistence, team tenancy or cross-device synchronization. Protect the backend with deployment access controls before an external rollout.
- A production bundle-size warning remains (main bundle approximately 776 KB uncompressed). It does not prevent the build or tested flows.
- Docker was not run because no engine was available. The Docker build's npm install/build steps were exercised locally from clean lockfiles; container execution itself remains unverified.
- No Railway deployment was performed. Existing deployed pages will not change until this full source is committed/deployed.
- Passing these bounded checks does not establish that software or model output is 100% bug-free.

FIXES APPLIED TOGETHER
1. One Docker stage builds and runs at /app, eliminating the cross-stage dist copy.
2. Required source files and contract JSON paths are checked before installation.
3. Both dependency locks are included; missing locks trigger an explicit npm install warning. Invalid or mismatched locks fail. Existing valid locks use npm ci.
4. Frontend development dependencies are installed explicitly even under NODE_ENV=production.
5. Build explicitly targets dist and verifies index.html, referenced compiled assets, JSON contracts, and a release marker.
6. Production refuses to start with missing assets instead of reporting a running but unusable service.
7. Production browser API requests use the server origin, including when testing an image on localhost. Vite development retains the local API port.
8. Readiness /api/ready is separate from AI-provider availability. The server binds 0.0.0.0 and honors PORT.
9. Docker context allows only build inputs; local dependencies, old dist, documents, logs and secrets are excluded. The image runs as an unprivileged user and removes frontend build dependencies.
10. Render settings and optional Blueprint replace Railway-specific delivery instructions.
11. A distinct release identifier lets you check the deployed version through /release.json and /api/ready.
12. A real Linux container build/start/assets workflow is included for GitHub Actions; it has not been executed here.
